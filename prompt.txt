KEYGO — MAJOR IMPLEMENTATION SPRINT
Project Intelligence → Coding Agent → Safe Editing → Testing → Verification
Mission
KeyGo currently has the foundational architecture for a local-first Windows AI development environment:

.NET/C#
AI provider abstraction
Multiple AI providers
Secure API credential handling
Model selection/routing foundation
Local project support
Usage/token/cost tracking
Permission system
Desktop application shell
Tests
Architecture/security documentation

The next milestone is to transform KeyGo from an AI workspace into a real AI coding agent.
The target workflow is:
User Goal
   ↓
Understand Project
   ↓
Investigate
   ↓
Plan
   ↓
Show Plan
   ↓
User Approval
   ↓
Generate Changes
   ↓
Show Diff
   ↓
User Approval
   ↓
Apply Changes
   ↓
Run Tests
   ↓
Analyze Results
   ↓
Fix Safe Problems
   ↓
Run Tests Again
   ↓
Final Review
   ↓
Report

The agent must be powerful, but never mysterious.
Every consequential operation must be observable, permission-controlled, and reversible where practical.

1. IMPORTANT: INSPECT THE EXISTING SYSTEM FIRST
Before implementing anything:
Inspect the entire existing architecture.
Pay particular attention to:
Core
Runtime
Provider adapters
AI abstractions
Project services
Permission system
Security layer
SQLite
Chat
Usage tracking
Desktop UI
Tests
Documentation

Determine what already exists.
Do NOT create duplicate implementations.
If an existing abstraction is good, extend it.
If something is incomplete, finish it.
If something is architecturally wrong, refactor it carefully with tests.
Do not rewrite the entire application.

7. PERMISSION ENGINE
The permission engine must be an actual enforcement layer.
Not merely UI.
Example:
Tool                 Permission
───────────────────────────────
ReadFile             READ
SearchFiles          READ
GetGitStatus         READ

CreateFile           WRITE
ModifyFile           WRITE
DeleteFile           DELETE

RunCommand           EXECUTE
RunTests             EXECUTE

GitCommit            GIT_WRITE
GitPush              NETWORK_WRITE

The agent cannot bypass these permissions.

8. DEFAULT AGENT MODE
Default:
OBSERVE

The agent can:
✓ Read
✓ Search
✓ Analyze
✓ Inspect Git
✓ Build plans

Cannot:
✗ Modify files
✗ Delete files
✗ Run arbitrary commands
✗ Commit
✗ Push

13. CHANGE GENERATION

14. DIFF ENGINE

where safe and possible.

20. TERMINAL SECURITY
Terminal execution is dangerous.
Create a command policy.
Classify commands:
SAFE
REVIEW_REQUIRED
DANGEROUS
BLOCKED

Examples:
dotnet test
SAFE

npm test
SAFE

git status
SAFE

npm install
REVIEW_REQUIRED

rm -rf
BLOCKED/REVIEW_REQUIRED

format disk
BLOCKED

Do not rely solely on string matching.
Use a structured command execution policy.

49. ENGINEERING PRINCIPLE
The goal is NOT:

"Make an AI that can control the computer."

The goal is:

"Make an AI that can perform serious software engineering work while the developer remains in control."

Every powerful capability should have:
Visibility
Permission
Auditability
Cancellation
Recovery

Build the system so future features such as:
Browser Agent
Computer Agent
Multi-Agent Company
Software Factory
VS Code integration
Autonomous Missions

can be added on top of this foundation without redesigning the core runtime.

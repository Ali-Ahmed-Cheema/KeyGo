KEYGO — CORE ALPHA DEVELOPMENT SPRINT
Role
You are the KeyGo engineering team.
The existing KeyGo repository already contains a .NET/C# prototype with:

provider abstraction
model routing
local credential architecture
usage tracking
auditing
permission-aware project operations
desktop application shell
SQLite-related infrastructure
documentation
initial routing tests

Do NOT rewrite the existing architecture blindly.
First inspect the current repository and understand what is already implemented.
Your objective in this sprint is to transform the current prototype into a functional, testable KeyGo Core Alpha.

5. Provider Interface
Review and improve the existing provider abstraction.
A provider should expose capabilities similar to:
public interface IAIProvider
{
    string Id { get; }

    Task<ProviderConnectionResult> ValidateAsync(
        CancellationToken cancellationToken);

    Task<IReadOnlyList<AIModel>> GetModelsAsync(
        CancellationToken cancellationToken);

    Task<AIResponse> SendAsync(
        AIRequest request,
        CancellationToken cancellationToken);

    IAsyncEnumerable<AIStreamEvent> StreamAsync(
        AIRequest request,
        CancellationToken cancellationToken);
}

Adapt this to the existing architecture rather than blindly copying it.
The interface must remain provider-neutral.

7. API Key Security
Implement the real credential storage mechanism.
For Windows:
Prefer:
Windows Credential Manager

and/or:
DPAPI

depending on the final security design.
The exact mechanism must be documented.
NEVER store:
API keys in SQLite
API keys in JSON
API keys in logs
API keys in source code
API keys in environment files committed to Git

The database should store credential metadata/identifiers only.
Example:
Provider: OpenAI
CredentialId: abc123
Created: ...
LastUsed: ...

Never:
ApiKey: sk-xxxxxxxx

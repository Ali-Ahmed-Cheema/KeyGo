KEYGO — LARGE IMPLEMENTATION SPRINT
Provider Verification → Model Discovery → Working AI Chat → Usage Intelligence
Mission
The current KeyGo project is an early-alpha .NET/C# local-first AI workspace.
The existing project already contains foundations for:

AI provider abstractions
model routing
credential storage
usage tracking
auditing
permission-aware project operations
SQLite/local data
desktop application shell
tests
architecture/security documentation

The currently recommended next step is:

Provider verification and model discovery flow

However, do NOT implement this as an isolated small feature.
Build a large end-to-end vertical slice that transforms KeyGo from an architectural prototype into a usable AI application.
The completed flow should be:
Add Provider
      ↓
Securely Add API Key
      ↓
Verify Credential
      ↓
Discover Models
      ↓
Detect Capabilities
      ↓
Connection Inspector
      ↓
Select Model
      ↓
Start Chat
      ↓
Streaming Response
      ↓
Usage Tracking
      ↓
Cost Estimation
      ↓
Persistent Conversation

The result should be a functioning KeyGo Core Alpha.

5. CREDENTIAL VERIFICATION
Implement the complete verification workflow.
User selects:
Add AI Provider

Then:
Provider:
[ OpenAI ▼ ]

API Key:
[ **************** ]

[ Connect ]

KeyGo must:

Receive credential securely.
Store it using the existing secure credential architecture.
Never write plaintext key to SQLite.
Never write plaintext key to logs.
Attempt provider authentication.
Determine whether the credential is usable.
Return a structured result.

Possible results:
CONNECTED
INVALID_CREDENTIAL
RATE_LIMITED
INSUFFICIENT_CREDITS
NETWORK_ERROR
PROVIDER_ERROR
UNKNOWN

Do not confuse:
Invalid key

with:
Provider temporarily unavailable

38. SUCCESS CRITERIA
At the end of this sprint, KeyGo should no longer be merely:

"A prototype containing provider abstractions."

It should be:

A functioning local-first multi-provider AI workspace capable of securely connecting an API credential, verifying the provider, discovering models, inspecting capabilities, selecting a model, running real streaming conversations, persisting chat history, and tracking usage/cost.

# Most Important Rule

Since you've already chosen a **Backend-First Approach**, the frontend team should **not start inventing backend behavior**.

The workflow should be:

```text
                    BACKEND
                       │
                 API / IPC Contract
                       │
                       ▼
                  FRONTEND
                       │
        ┌──────────────┼──────────────┐
        ▼              ▼              ▼
       UI            State          UX
        │              │              │
        └──────────────┼──────────────┘
                       ▼
                    User
```

For every frontend feature, define:

```text
Feature
↓
Screen
↓
Components
↓
User Actions
↓
API/IPC endpoint
↓
Request
↓
Response
↓
Loading state
↓
Success state
↓
Error state
↓
Empty state
```

**For KeyGo specifically, I would prioritize the frontend MVP as:**

> **App Shell → Dashboard → Chat → Providers → Models → Projects → Code Editor → Agents → Permissions → Missions → Usage/Costs → Settings**

That gives you the actual **KeyGo product experience** without trying to implement every advanced feature in the 3,600+ line specification at once. The specification itself recommends progressively adding the advanced marketplace, local models, computer control, multi-agent factory, and advanced automation after the core runtime/chat/workspace/agent foundation.
